# تست صدای حسین و زیرنویس هنگام صحبت

صفحهٔ فعال: **https://hossein.asr-gooyesh.ir/test-voice**

با حساب معمول برنامه وارد شوید. در صفحهٔ ضبط، پیوند «تست صدای حسین» بالای فهرست اضافه
شده است. دکمهٔ بزرگ میکروفن، دریافت صدا را شروع و متوقف می‌کند. اجازهٔ میکروفن
باید در مرورگر داده شود. متن موقت تقریباً هر دو ثانیه با دریافت پاسخ مدل اصلاح
می‌شود؛ با ۲٫۵ ثانیه مکث یا توقف میکروفن، آخرین بخش تکمیل می‌شود. نوشته را
می‌توان کپی یا پاک کرد. دقت مدل کامل نیست.

## معماری اجرا

- برنامهٔ اصلی روی 3060: `/home/gooran/Desktop/hossein-data/recorder`، پورت 8765.
- سرویس مدل روی همان سرور: `/home/gooran/hossein-asr-live`، واحد کاربری systemd
  به نام `hossein-asr.service`، فعال در شروع سیستم با linger کاربر موجود.
- وزن دقیقِ خروجی آموزش: `shenava-hossein.nemo` با SHA256
  `4d96d24f154b1dfbf23c5c8914274d339d1dfa2f4eadf23ff725009a44d7f9c0`.
- مدل NeMo 3.0.0، PyTorch 2.11.0+cu126، سر CTC، همان context `[70,13]` و
  توکنایزر همراه مدل. محیط موجود `.venv-shenava` به کار رفته است.
- سرویس فقط روی gateway شبکهٔ داخلی recorder یعنی `172.19.0.1:8791` گوش می‌دهد.
  این آدرس از gateway کانتینر `recorder_default` در زمان نصب گرفته شده است؛ اگر
  این شبکه تغییر کرد، آدرس واحد systemd و `HOSSEIN_ASR_URL` باید با هم اصلاح شوند.
- درخواست مرورگر از همان دامنه و با نشست ورود موجود به `/api/live/transcribe`
  می‌رسد؛ پروکسی داخلی آن را به مدل می‌فرستد. وضعیت مدل هم در
  `/api/live/status` نیاز به ورود دارد. توکن Hugging Face در سرویس وجود ندارد.

مرورگر با AudioWorklet صدا را می‌گیرد، پیوسته به mono 16 kHz تبدیل و به PCM
علامت‌دار ۱۶ بیتی little-endian تبدیل می‌کند. جملهٔ در حال دریافت هر دو ثانیه
به مدل فرستاده می‌شود؛ پاسخ، متن موقت همان جمله را جایگزین می‌کند. سکوت برای
پیدا کردن پایان جمله استفاده می‌شود و صوت آرام حذف نمی‌شود. هر بخش حداکثر
۳۰ ثانیه است؛ حداکثر ورودی سرور ۴۰ ثانیه است. این روش بازشناسی تکرارشوندهٔ
بخش‌های در حال رشد است؛ streaming با cache داخلی مدل پیاده‌سازی نشده است و
ممکن است در مرز بخش‌های ۳۰ ثانیه‌ای کلمه‌ای اشتباه تشخیص داده شود.

صوت و نوشتهٔ تست در فایل، دادگان یا history سرور ذخیره نمی‌شود. متن فقط تا زمان
باز بودن صفحه در حافظهٔ مرورگر می‌ماند و صوت برای پردازش در RAM نگه داشته می‌شود.
گزارش HTTP شامل متن گفتار یا بدنهٔ درخواست نیست. صف مرورگر تنها تازه‌ترین نسخهٔ
موقت هر جمله را نگه می‌دارد. یک قفل، فراخوانی هم‌زمان GPU را محدود می‌کند؛ پاسخ
429 با تلاش مجدد کوتاه در مرورگر مدیریت می‌شود.

## نصب و نگه‌داری

`install_recorder.py` فایل‌های recorder را با بررسی محل‌های دقیق تغییر می‌دهد و
پیش از تغییر، نسخهٔ اصلی را در پوشه‌ای کنار recorder نگه می‌دارد. به فایل‌های
کاربران، داده‌های مرجع و ضبط‌ها دست نمی‌زند. اجرای دوباره روی نصب موجود متوقف
می‌شود تا تغییرهای قبلی بی‌صدا دوباره اعمال نشوند.

```bash
# در سرور 3060، با فایل‌ها و مدل موجود در /home/gooran/hossein-asr-live:
python3 /home/gooran/hossein-asr-live/install_recorder.py \
  --recorder /home/gooran/Desktop/hossein-data/recorder \
  --asr-url http://172.19.0.1:8791
```

پس از نصب اولیه، Docker image برنامه با `docker compose up -d --build recorder`
بازسازی می‌شود. نمونهٔ unit در `hossein-asr.service` قرار دارد. برای نگه‌داری:

```bash
systemctl --user status hossein-asr.service
journalctl --user -u hossein-asr.service -n 40
systemctl --user restart hossein-asr.service
```

برای بازگردانی نصب اولیه، فایل‌های `server.py`، `static/app.html`،
`static/login.js`، `Dockerfile` و `docker-compose.yml` را از پوشهٔ پشتیبان کنار
recorder برگردانید و فقط سرویس recorder را بازسازی کنید. فایل‌ها و دارایی‌های
افزودهٔ تست می‌توانند تا زمان بررسی بعدی باقی بمانند. با
`systemctl --user disable --now hossein-asr.service` اجرای مدل متوقف می‌شود.

## بررسی‌ها

```bash
node test_capture.cjs
node test_page.cjs
python test_proxy.py
```

تست‌ها نرخ‌های 16/44.1/48 kHz، حفظ صوت در مرز بافر و هنگام توقف، صدای آرام،
مرز جمله و ورودی طولانی، اصلاح متن موقت، انتظار برای پاسخ نهایی، آزاد کردن
میکروفن، خطای اجازهٔ میکروفن، کپی/پاک کردن و احراز هویت/محدودیت اندازهٔ درخواست
را پوشش می‌دهند. تست چرخهٔ میکروفن با ورودی مجازی اجرا می‌شود.

`verify_deployment.py` روی 3060 از مشخصات ورود محلی موجود، بدون چاپ یا ذخیرهٔ
آن‌ها، استفاده می‌کند. برای آزمون سه نمونهٔ تست در برابر خروجی ارزیابی اصلی،
`expected_ctc.json` باید کنار اسکریپت از خروجی ارزیابی کپی شده باشد. این
فایل و نمونه‌های صوتی جزو این کد نیستند.

در اجرای واقعی، سه فایل ۱۰٫۸ تا ۲۳٫۹۴ ثانیه‌ای در مسیر HTTPS عمومی، حدود
۱۹۰ تا ۲۸۰ میلی‌ثانیه رفت‌وبرگشت داشتند و متن هر سه با خروجی ارزیابی مدل برابر
بود. این زمان، دورهٔ جمع‌آوری دوثانیه‌ای صوت در مرورگر را شامل نمی‌شود. گزارش
`deployment_verification.json` هویت مدل، رد درخواست بدون ورود، دارایی‌های صفحه،
صوت مرجع و فهرست recorder را هم بررسی می‌کند. پخش فیزیکی میکروفن کاربر در این
آزمون خودکار انجام نشده است.
